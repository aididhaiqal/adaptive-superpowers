# Bounded Native Delegation

Delegate when independent work, specialist judgment, or bulky investigation justifies the coordination and context cost. The host controls available tools, roles, model/effort choices, concurrency, and depth; this bundle imposes no global count or depth cap and requires no delegation quota.

- Give each agent one owned outcome, relevant paths/interfaces, accepted requirements and binding constraints, verification expectations, and a concise return contract. Use fresh focused context where supported; pass large evidence by file rather than accumulated session transcripts.
- Parallel implementation is appropriate when edits and dependencies do not collide. Keep coupled work together, assign integration ownership, and coordinate shared contracts before editing. Do not split merely to occupy agents.
- Batch small same-shape changes under one owner when they share verification and review needs. Preserve each requested file/outcome in the batch acceptance.
- Nested delegation is allowed only when the host and assigned role permit it and distinct subscopes justify the cost. Children cannot gain broader scope or authority than their assignment. Read-only assignments remain read-only throughout their descendants.
- Assign review ownership once at each necessary boundary. Do not commission a duplicate review of the same range and risks; additional specialists need a distinct question or evidence gap. Workers return unresolved user decisions to the parent rather than restarting project-wide brainstorming.
- Resume the existing implementer for bounded corrections when its context remains useful. Provide the findings, changed evidence, and affected verification; re-review fixes and their impact, not unrelated work. If progress stalls, change the hypothesis, brief, or expertise instead of repeating unchanged dispatches. A retry limit never authorizes parking a blocking defect or weakening acceptance.

Continue useful local work while agents run. When genuinely waiting, use the host's event-driven wait/notification mechanism within its responsiveness limits; avoid repeated status polls. Tool syntax and role configuration belong in host documentation, not shared policy.
